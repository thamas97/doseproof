3 Shared model and source contracts
Proposed implementation choices for the Day 1 agreement follow. They make handoffs concrete and can be changed together before integration. They are teaching settings, not real treatment operating limits.
Contract
Agreed starting proposal
One plant engine
model.py, controller.py, sensors.py, desk.py and events.py in one Python application. One loop owns state; desk commands enter through an internal queue.
Teaching baseline
One-second tick; flow 10 L/s; accepted feed 15 mg/s; demand 0.50 mg/L; initial residual 1.00 mg/L.
Delayed response
For positive flow, target = max(0, actual feed / flow − demand). Delay four ticks, then move residual one fifth of the difference toward that target each tick.
Approved step
Change accepted feed from 15 to 20 mg/s. Actual feed changes first; residual then tends from 1.00 toward 1.50 mg/L after the teaching delay.
Equipment modes
No flow stops delivery without division; stopped pump gives zero delivery; reduced delivery uses factor 0.5; ignored command retains prior accepted feed.
Reset and pause
Pause freezes simulation steps. Reset clears queues/faults and restores initial state/seeds. Create a new run ID and preserve prior source files.
Two sensor sources
A and B sample residual, with separate source IDs and Random seeds 101/202. Proposed noise is bounded at ±0.01 mg/L.
Sensor modes
Missing suppresses samples; delayed emits five seconds late with original sample time; stuck holds a measurement; bias adds +0.40 mg/L to one source.

Event envelope and source ownership
Each producer supplies schema_version, run_id, event_id, source_id, source_seq, event_type, source_timestamp_utc, emitted_at_utc and sim_step. Add value, unit and quality for observations; actor, equipment, chemical, target and approval expiry for actions. Share change_id through the action trail where known; sensor samples normally use null change_id.
Use JSONL, one complete event per line, under evidence/<run_id>/. A common writer preserves original IDs and times. Unknown fields use null plus a reason. Label illustrative fixtures separately from captured runtime records. Both sensors share software and a laptop; their independence is limited.
Repeatability compares residual and sensor values by relative simulation step using the same saved parameters and seeds. Fresh run IDs, unique event IDs and different UTC timestamps are expected. Source collection, normalization and assurance verdicts remain in layers 2–8.

30 Scenario checks and practical troubleshooting
Before each case, save the current run, reset the named scenario and record run ID, seeds and starting step. Change one fault at a time. Save actual observations rather than screenshots of a configured switch.
Case
Action and expected observation
Baseline and approved
Run baseline at 10 L/s and 15 mg/s, then a different-user approved 20 mg/s change. Actual delivery changes before residual tends toward 1.50 mg/L; retain the common action change ID.
Lab unapproved
Deliberately enable the labelled local lab action. Actor/command/ack records exist and approval is absent. Restore normal mode afterwards.
Equipment faults
No flow gives zero delivery without division error; ignored command retains the prior accepted value; stopped pump gives zero actual feed; reduced mode gives half delivery.
Missing and delayed A
B continues. Missing A ages/unavailable without fresh zero. Delayed A retains original sample time and shows age.
Stuck and biased A
Stuck A holds a value while time/sequence may advance. Bias A adds its offset. Compare with changing model/B; apparent good quality alone does not prove correctness.
Desk negatives
Anonymous request, self-approval, expired/mismatched approval and duplicate execution are refused server-side. Check no normal command was executed.
Observer and restart
Observer reads succeed; attempted observer writes are denied and plant state stays unchanged. Stop observer and confirm ticks continue. Restart from saved state; replay by simulation step.

Resolve the most likely blockers
No Modbus connection: check the controller terminal, 127.0.0.1:1502 and device 1. Wrong reading: check Holding Registers, protocol address versus FUXA address, UInt16 and one conversion. A value of 100 instead of 1.00 usually means no scale; a value near 0.01 usually means double division.
Sensor stale while FUXA is connected: inspect sensor source time/age, not just device connectivity. Reset mismatch: clear delay queues and restore each source seed. Missing project after restart: verify the same FUXA state folder; JSON import is recovery, not normal restart. Save exact install or port errors and escalate within the timebox.
